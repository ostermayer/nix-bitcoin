## Audit report: ostermayer/nix-bitcoin @ b314aa9 (snapshot 2026-10-01)

**Method.** Mapped the trimmed surface (bitcoind, lnd + lndinit/lndconnect, electrs, btcpayserver/nbxplorer, plus secrets, onion, netns, backups, wireguard preset, operator, deployment, CI). Read the in-repo audit trail (docs/security-audit-2026-08-14.md and its resolution log, then the 2026-08-29/30 and 2026-09-09 hardening commits). Verified each documented fix actually holds in this tree. Resolved the live pinned versions with nix eval. Diffed the three commits made after the last documented audit pass for regressions. Swept all modules, pkgs, helper, and CI code for the classic patterns: 0.0.0.0 binds, secret file modes, argv-borne secrets, root code following user-writable symlinks, fail-open gates.

**Pinned versions, verified live.** nixpkgs 2026-09-30, unstable 2026-09-29 (fresh for the snapshot date). bitcoind 31.1, lnd 0.21.3-beta, btcpayserver 2.4.4 (the security release, via the version-guarded override), nbxplorer 2.6.10, electrs 0.11.0, tor 0.4.9.13 (past the 2026-09-08 security release), lndinit 0.1.36-beta. No stale pins found.

**Prior fixes verified present, with regression tests pinning them.**
- lnd macaroon minting (modules/lnd.nix): root script stages in a root-only mktemp dir, reads admin.macaroon as the lnd user, caps and validates the response, moves with `mv -fT`. The test suite even plants a root-only canary through a symlink and asserts the exfiltration fails.
- onion-addresses (modules/onion-addresses.nix): root rebuilds user dirs from scratch each run, refuses symlinked sources, validates one v3 onion address before splicing it into daemon configs.
- setup-secrets: sandboxed root service, stray files locked to root 0440, dotglob covered.
- wireguard preset: asserts the firewall is on and nftables is off when the REST admin API is exposed; accept rule pinned to the wg interface and single peer; restrictPeer REJECT inserted at chain top so it cannot sit behind default accepts.
- netns-exec: absolute-path exec, capability checks, whitelist matches the five live netns.
- cve-scan.sh: fails closed on every bad exit code, non-JSON output, malformed entries, and non-numeric counts. Whitelist entries are per-CVE scoped for collisions, with review dates.
- CI release-gates the wireguard scenario; the CVE scan target is the real runtime closure with the secure-node preset.
- HEAD commit b314aa9 itself (nbxplorer WorkingDirectory + reload-watcher off) is a sound hardening fix: immutable app dir as content root, which also blocks a planted appsettings.json, and a test asserting cwd and inotify watch count.

**Result.** No new high or critical findings. The open items are the documented, consciously deferred or accepted set. The one medium is real and should stay on the tracker until the second-listener variant in docs/wireguard-rest-bind.md ships.
