**Highest-value targets examined in depth:** the root-privileged `+`-prefixed ExecStartPost scripts (lnd macaroon creation), setup-secrets/generate-secrets, onion-addresses (root + CAP_DAC_OVERRIDE), netns-exec and netns setup, the wireguard preset's firewall/REST exposure, btcpayserver/nbxplorer privilege wiring and RPC whitelists, backups, CI scripts, and the packaging layer (btcpayserver 2.4.3 copy, overrides.nix guard, fetch-node-modules).

## Verified good

onion-addresses root service (symlink refusal + content validation + root-built dirs + `chown -h`), macaroon staging (root-only mktemp + atomic rename, write side), secrets dir hygiene (root-owned 0751 dir, per-file ownership, unlisted files locked to root 0440, `umask` 0600 for generated secrets), no secrets in the store (all `toFile`/`writeText` configs are secret-free; passwords appended post-install at 0600), electrs/nbxplorer/btcpayserver configs written `install -m 600`, netns-exec (absolute path, whitelist, caps dropped, returns checked), default binds all localhost, RPC whitelists trimmed of DoS/wallet methods, cookie 0640 explicit, CVE-scan fail-closed logic, postgres auth via peer sockets with per-service DBs.

## Key finding

The 2026-08-24 macaroon fixes closed the write side of the root ExecStartPost but left the read side open: root reads `admin.macaroon` through the lnd-writable datadir with no symlink guard, and the bytes it reads are sent straight back to lnd as an HTTP header. That is an arbitrary root-file-read exfiltration channel for a compromised lnd, triggerable on demand via self-crash restarts.
