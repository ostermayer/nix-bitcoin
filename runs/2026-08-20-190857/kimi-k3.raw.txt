Investigation complete. Here's what I mapped and what survived scrutiny.

## What I audited

Full sweep of `modules/` (secrets, lnd, bitcoind, electrs, btcpayserver, onion-addresses/services, netns-isolation, operator, security, nodeinfo, backups, presets, deployment), `pkgs/lib.nix`, netns-exec source, helper scripts, and the `audits/` runner. The fork has clearly been self-auditing (b2eb47f, be5e094, 8611a39), so I focused on what those fixes missed.

**Cleared after reading the code:** no secret values reach the Nix store (all `$(cat ${secretsDir}/...)` uses are runtime preStart scripts writing runtime files); the RPC whitelist is tight (`signrawtransactionwithkey`/`signmessagewithprivkey` are stateless, keys-as-args); fetchers are hash-pinned; onion-addresses.nix is now symlink-safe; netns-exec drops caps before exec; the bitcoind cookie group-read is documented design; electrs/nbxplorer credential files are protected by 0770 parent dirs.

## Finding 1 (high): lnd root ExecStartPost reads `admin.macaroon` through an lnd-controlled path

`modules/lnd.nix:263` builds a root script (`nbLib.rootScript` = `"+"` prefix, so unsandboxed root), and line 280 does:

```
adminMacaroonHex=$(${pkgs.xxd}/bin/xxd -ps -u -c 99999 '${networkDir}/admin.macaroon')
```

`networkDir` is `/var/lib/lnd/chain/bitcoin/<network>` — every component from `/var/lib/lnd` down is owned and writable by the `lnd` user. Commit b2eb47f fixed the *write* side of this script (staging in a root-only dir, atomic rename) with an explicit comment that root must never operate "through a path the lnd process could tamper with" — but the *read* of `admin.macaroon` still follows symlinks as root. The file's hex content is then POSTed as the `Grpc-Metadata-macaroon` header to lnd's own REST endpoint. A compromised lnd process (lnd is P2P/onion-exposed and holds hot funds, exactly the daemon this sandboxing defends against) replaces `admin.macaroon` with a symlink to e.g. `/etc/nix-bitcoin-secrets/backup-encryption-env`, `bitcoin-rpcpassword-privileged`, `/etc/shadow`, or `/root/.ssh/id_*`; lnd skips macaroon recreation at startup because `stat` through the symlink succeeds (secretsDir is 0751); the attacker kills the process (`Restart=on-failure`, 10s) and the restarted, still-attacker-controlled REST server receives the target file's contents in the request header. Payoff: lnd-user → arbitrary root file read → bitcoind full-access RPC, backup passphrase (backups include `/var/lib/lnd` with the seed), root SSH keys. Only fires when `services.lnd.macaroons` is non-empty — which the btcpayserver lnd-backend sets, so the canonical deployment hits it.

## Finding 2 (medium): audit sandbox masks two paths; the rest of the home dir and host `/proc` stay readable with open egress

`audits/run.sh:81-85` bwraps the model with `--ro-bind / /` and masks only `~/.ssh` and `~/.config/fork-audit`. I verified from inside: `~/.config/google-chrome` (46 entries), Brave, Mozilla profiles all readable; 525 host processes visible and `/proc/<pid>/environ` of same-UID processes accessible (I did not read them); network egress is shared (my own API traffic proves it). The publish scrub (line 134) knows only four API keys plus the two SSH key bodies and PEM blocks, and is exact-substring per line, so transformed content passes. The runner's own prior self-audit logic — "shell + network + readable secret = exfiltration-capable regardless of scrub" — applies to everything still readable. Prompt-injection surface remains via the audited repo content itself (public repo, PRs welcomed to `prompt.md`). The crown-jewel deploy/sign keys are masked and this host has no ssh-agent and an empty pi `auth.json` and empty `private-keys-v1.d`, which is why this is medium, not high.

## Finding 3 (info): hardened preset re-enables unprivileged user namespaces

`modules/presets/hardened.nix` imports the NixOS hardened profile, then sets `security.allowUserNamespaces = true`, undoing one of the profile's kernel-exploit-surface reductions. Justified in a comment (nix sandboxed builds need it), so it's a deliberate tradeoff — but "hardened" consumers should know the boundary they actually get.
