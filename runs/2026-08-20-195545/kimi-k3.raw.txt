## Audit summary

**Surface mapped.** The fork is a trimmed nix-bitcoin: `modules/` (bitcoind, lnd, electrs, btcpayserver/nbxplorer, secrets, onion-addresses/onion-services, netns-isolation, operator, security, lndconnect, nodeinfo, backups, presets, krops/nixops deployment), `pkgs/` (lib.nix hardening helpers, the `netns-exec` cap_sys_admin wrapper, lndinit/nbxplorer packages, empty overrides.nix), `helper/` scripts, `audits/run.sh`, and three CI workflows. I focused on the funds-reachable paths: secrets handling, lnd's macaroon/seed flow, the RPC whitelist, the root-privileged onion-addresses copier, and the tor→service trust boundary.

**Verified clean (hypotheses disproved by reading):**
- **Secrets in store**: every secret is referenced by runtime path and read via `$(cat /etc/nix-bitcoin-secrets/...)` in preStart scripts, never interpolated at eval time. `lnd.conf`/`settings.config` are `install -m600`; the rpcauth password is passed via file, not argv.
- **lnd macaroon staging** (`lnd.nix` ExecStartPost): root-only `mktemp -d` staging on the same tmpfs + atomic rename into `/run/lnd`; a symlink planted by the lnd user at the destination is replaced, not followed. The `+` prefix bypassing `PrivateUsers=` is consistent with onion-addresses needing an explicit `PrivateUsers=false` (its main ExecStart can't use `+`), and the flow is CI-tested.
- **RPC whitelist**: public list has no wallet/stop/import calls; `signrawtransactionwithkey` takes keys as args only; `rpcwhitelistdefault=0` correctly leaves `privileged`/cookie unrestricted (bitcoind semantics: `0` = unlisted users unrestricted). btcpayserver inherits the public list.
- **netns-exec**: owner-only 0500, absolute-path execv, exact netns whitelist, caps dropped before exec.
- **Supply chain**: all fetchers hash-pinned, nixpkgs via flake.lock narHash, GitHub Actions SHA-pinned.
- All M-1..M-8/Low fixes from the prior audit (docs/security-audit-2026-08-14.md) are present and correct.
