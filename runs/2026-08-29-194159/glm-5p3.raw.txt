# Security Audit — nix-bitcoin fork @ 1caa0af

## Scope and method

Full-tree audit of the trimmed fork (bitcoind, lnd, electrs, btcpayserver/nbxplorer + infrastructure), at commit `1caa0af` ("cve-scan: fix two fail-open bugs"). Method: read every module in `modules/`, all `pkgs/`, `helper/`, CI workflows and scripts; verified each recent audit-fix commit (`121406c`, `b2eb47f`, `be5e094`, `821b5e8`, `1caa0af`, `19517ec`, `a6dbbd8`) against its claimed fix; empirically tested umask math; traced secret flows end-to-end; cross-checked against the fork's own audit history (`docs/security-audit-2026-08-14.md`, resolution log) for regressions and residual items.

## Surface map

| Area | Files | Risk class |
|---|---|---|
| Secrets framework | `modules/secrets/secrets.nix` | secret-to-store leaks, perms, shell injection |
| bitcoind | `modules/bitcoind.nix`, `bitcoind-rpc-public-whitelist.nix` | RPC exposure, cookie, config splice |
| lnd | `modules/lnd.nix`, `lndconnect.nix` | macaroon symlink races, wallet/seed perms, REST bind |
| Onion | `onion-services.nix`, `onion-addresses.nix` | root-service symlink/TOCTOU, hostname injection into conf files |
| Netns | `netns-isolation.nix`, `pkgs/netns-exec` | wrapper priv-esc |
| Web stack | `btcpayserver.nix` (nbxplorer, postgres) | RPC/macaroon grants to internet-facing app |
| Presets | `secure-node`, `hardened(-extended)`, `enable-tor`, `wireguard`, `bitcoind-remote` | exposure defaults |
| Supply chain | `flake.lock`, `pkgs/*` fetches, `overrides.nix`, `helper/*`, CI | pin integrity, fail-open scans |

## Verified clean (highest-value targets)

- **onion-addresses**: the injection/TOCTOU fix is correct. Content validated once into a variable against `<56×base32>.onion`; output dirs built root:root 0700 and only handed to users after population (dataDir is 0751 root:root, so users cannot race `rm -rf ./*` → `mkdir`); all chowns use `-h`; `install -T` writes only into freshly-created root-owned dirs. No write-through-symlink path remains.
- **lnd macaroon staging**: root-only `/run/lnd-macaroons.XXXXXX` (mktemp 0700) + `mv` on the same tmpfs = atomic `rename(2)` that replaces a lnd-planted symlink at `/run/lnd/<name>.macaroon` without following it. A compromised lnd can feed bytes to the target user's macaroon file, but that grants nothing lnd doesn't already have. Verified by `test/tests.py` (`btcpayserver.macaroon` REST call).
- **setup-secrets**: no secrets in the store (rpcauth lines, rpcpass, HMACs only assembled at runtime); all interpolations `escapeShellArg`-quoted; dir root:0700 during generation; unprocessed files locked to root 0440. The rpcauth fix reads the password from file into same-process `sys.argv` — it never appears on a process cmdline.
- **CVE scan**: now fail-closed (build failure, vulnix rc ∉ {0,2}, and non-array JSON all fail the job before the workflow can close the tracking issue; the `affected_by`-only filter correctly reports scoped-collision + new-CVE packages).
- **netns-exec**: allowlist of live netns, absolute-path `execv`, caps dropped before exec, owner-only mode 500 wrapper.
- **bitcoind cookie** 0640 (test-asserted), **electrs.toml** 0600, btcpayserver RPC user over-grants (`setban`, `generatetoaddress`) removed; public whitelist DoS/wallet methods removed with documented rationale.
- **Supply chain**: all fetches hash-pinned HTTPS; krops pinned to commit; no `curl | bash`; examples/flakes pin `github:ostermayer/nix-bitcoin/release`; release-tag workflow uses minimal permissions.

## Findings

One medium (already documented as deferred by the fork's own process, still open in code), two low consistency defects, one stale doc, and three informational hardening notes. No high-severity unfixed vulnerability found.

**Bottom line:** the fork's fix history holds up under adversarial re-review — the macaroon race, onion hostname injection, and CVE-scan fail-open fixes are all correctly implemented. The one open exposure worth real attention is F-1, which already has a complete, reviewed remediation plan sitting in `docs/wireguard-rest-bind.md` waiting to be implemented; F-2 and F-3 are one-line consistency fixes in the fork's own tooling.
