All hypotheses verified or discarded. Summary of what I checked and what survived:

**Surface mapped:** the fork ships bitcoind, lnd (+lndconnect), electrs, btcpayserver/nbxplorer, plus secrets, netns-isolation, onion-addresses/services, operator, presets, and pkgs (netns-exec, lndinit, nbxplorer, krops) and helper scripts.

**Checked and found clean (no finding):** no secret values reach the Nix store — all RPC passwords/HMACs are spliced at runtime in `preStart` via `$(cat ${secretsDir}/...)`; the store-side `bitcoin.conf`/`lnd.conf`/nbxplorer/btcpayserver configs carry no secrets. `setup-secrets` locks undeclared files to `root: 0440` and the dir is 0700 during generation. `defaultHardening` is applied to every daemon, and `nbLib.allowedIPAddresses` is correctly merged last in each service. The public RPC whitelist has no wallet/`stop` methods (`signrawtransactionwithkey` takes keys by argument; bitcoind runs with wallet disabled paths documented). `netns-exec` is owner-`0500`, file-capped, whitelists this fork's netns names, requires absolute exec paths, drops caps. The wireguard preset's earlier self-sed root-RCE (L-8) and the lndconnect 0.0.0.0 rebind (M-2) are genuinely fixed. The operator's doas/sudo run-as-lnd rule is root-equivalent by design (documented trust boundary). Fetchers are all hash-pinned; `fetch-release` GPG-verifies against a pinned fingerprint.

**What survived scrutiny:**

1. **`modules/lnd.nix:267-275` — root `ExecStartPost` follows symlinks in the lnd-owned `RuntimeDirectory`.** `rootScript` prefixes `+`, which lifts `User=` *and all sandboxing* for that command. The script writes `> "$RUNTIME_DIRECTORY/btcpayserver.macaroon"` and then `chown`s it *without `-h`* — but `/run/lnd` (mode 711) is owned by the `lnd` service user, who can plant `btcpayserver.macaroon` as a symlink to any path. On the next lnd start/restart, root truncates/rewrites the target (arbitrary-file clobber, e.g. `/etc/nix-bitcoin-secrets/lnd-wallet-password`, bitcoind state, `/etc/passwd`) and `chown`s it to the btcpayserver user. This is exactly the symlink-privesc class the fork fixed in onion-addresses (M-4, commit 8c2c342), still live here.

2. **`modules/btcpayserver.nix:110-112` — the btcpayserver/nbxplorer RPC user keeps `setban`.** The password file is group-readable by group `nbxplorer`, and the btcpayserver user is in that group. In the default (non-netns) layout, a compromised btcpayserver (an internet-facing app with a critical-CVE history) can read the RPC password and combine `setban` with the whitelisted `getpeerinfo` to strip bitcoind of honest peers — eclipse groundwork for double-spending on-chain payments the node accepts.

3. **`modules/onion-addresses.nix:89-98` — residual TOCTOU in the M-4 fix.** `-L $src` check and `install` are separate operations on a path under `/var/lib/tor/onion/<svc>/` that the `tor` user controls; a compromised tor can swap a symlink in between and have root copy an arbitrary file into a user-readable output.

4. **`helper/fetch-release` (and docs) still target upstream `fort-nix/nix-bitcoin`.** GPG verification passes against the pinned upstream key, so a fork user "upgrading" silently deploys unmaintained upstream code, losing every fork security fix with no signature failure to warn them.
