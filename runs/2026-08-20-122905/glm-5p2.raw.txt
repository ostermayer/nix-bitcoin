I've completed a thorough audit. Here's my narration, then the findings.

## Investigation summary

**Attack surface mapped.** This fork (commit 8611a39) ships only bitcoind, lnd (+lndinit, lndconnect), electrs, btcpayserver/nbxplorer, plus operator, secrets, onion, netns, backups infrastructure. It was already audited (`docs/security-audit-2026-08-14.md`) and patched (M-2/M-3/M-4/M-6, L-6..L-11). I focused where funds/keys/root are reachable.

**Secrets in store (#1 threat): clean.** Verified every `builtins.toFile`/`writeText` config (bitcoind, lnd, nbxplorer, btcpayserver) contains only paths, not secret values. HMACs/passwords are appended in `preStart` to dataDir copies (`install -m 600/640`). The L-6 fix correctly routes the rpcauth password through a file instead of argv; the lnd macaroon creation (`ExecStartPost` rootScript) passes the admin macaroon hex via a process-substitution fd and a shell variable, never argv. No secret reaches `/nix/store` or a `ps`-visible command line.

**File perms / symlinks: clean.** `setup-secrets` re-locks unprocessed files to `root:root 0440`, dir to `0751` (o+x but files are o=0); L-7 `escapeShellArg` applied. The dir is root-writable only, so non-root can't plant symlinks for the chown/chmod to follow. The M-4 onion-addresses fix is solid: symlink src refused, dirs built root:root then chowned last, `chown -h` throughout, dataDir-symlink refused.

**Privilege boundaries: tight.** No service joins group `bitcoin` (cookie = full privileged RPC) except bitcoind itself and the operator (intended, root-equivalent). lnd/electrs/nbxplorer join only `bitcoinrpc-public` (public-cred read). btcpayserver joins `nbxplorer` group. The lnd admin macaroon is lnd-only; the btcpayserver custom macaroon is scoped read + invoices/address write (no onchain/offchain write). netns isolation restricts each service to declared peers; btcpayserver has no path to bitcoind's RPC port even though its user holds btcpayserver-RPC creds.

**Sandboxing: solid.** `defaultHardening` (NoNewPrivileges, ProtectSystem=strict, PrivateTmp, capbounding=empty, seccomp) is applied to every funds daemon; overrides are justified (dotnet/lnd JIT → MemoryDenyWriteExecute=false). netns-exec requires absolute exec path, whitelisted netns, drops caps, owner-only 0500 wrapper.

**Supply chain: clean.** All fetchers hash-pinned HTTPS; krops pinned to commit hash; rpcauth.py fetchurl pinned; no `--impure`, no untrusted IFD, no remote patches. `fetch-node-modules` is unused by any deployed service.

**Ordering: reviewed.** The `requires`→`wants` change for lnd/electrs is availability, not a security regression (`after` still orders boot; lnd self-halts on chain-backend loss). Secrets target gates dependent services.

**What I did find** are two low-severity, evidenced items the prior audit's resolution notes glossed over. Neither is critical/high; I report them honestly with low confidence.
