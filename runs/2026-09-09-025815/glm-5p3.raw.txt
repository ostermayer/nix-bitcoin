# Audit report — ostermayer/nix-bitcoin @ d22c5da

## Surface map

**Deployed-node attack surface** (what a pinned `release` user runs): bitcoind (p2p via onion, RPC localhost/netns, cookie + HMAC users), lnd (p2p, gRPC/REST localhost/netns or wg-scoped, macaroon minting via root ExecStartPost), electrs (localhost/onion), btcpayserver + nbxplorer (localhost/onion, postgres via shared unix socket), tor (client + onion services), operator privilege ladder (doas/sudo as lnd, bitcoin group cookie access, netns-exec cap wrapper), secrets lifecycle (root generation/permissioning at boot), backups (duplicity as root). **Supply-chain surface**: flake.lock pins (nixpkgs 26.05 @ 93108a5, unstable @ 422d1ae, both ~1 day old at HEAD), version-guarded overrides, FOD hash-pinned package copies, CI (VM suite, CVE scan, release tagging), cachix cache, SSH-signed commits.

## Investigation highlights

The fork's own audit history (2026-08-14 through 09-09) is real in the code and re-verified here as effective: onion-addresses refuses symlinks, validates exact v3-onion content, and stages output dirs root-owned before handoff (closes the M-4 privesc and the hostname-injection chain into bitcoin.conf/lnd.conf); the lnd macaroon ExecStartPost stages in a root-only mktemp dir, reads admin.macaroon as the lnd user, caps and validates the lnd-controlled REST response under `set -eo pipefail`; setup-secrets escapes all interpolations, handles dotfiles, and locks strays to root 0440; the wireguard peer service uses a plain `wg set` (no sed-as-root RCE); netns-exec requires absolute paths with a trimmed netns whitelist; the public RPC whitelist drops the DoS/wallet methods; the cve-scan fails closed on build/NVD/JSON errors. Regression tests pin the important ones (macaroon read path, cookie mode, secrets lockdown, lnd-across-bitcoind-restart).

No exploitable high/critical was found in the fork's own code at this commit. The findings below are a monitoring-control gap, a documented deferred exposure, broken documented update paths with an unsafe escape hatch, an integrity-claim mismatch, and defense-in-depth/verification items.
