Audit complete. Summary of what I did and found:

## Surface map
Trimmed nix-bitcoin fork: modules for bitcoind, lnd (+lndconnect), electrs, btcpayserver/nbxplorer, plus secrets system, netns isolation, onion services, hardened presets, wireguard preset, helper scripts, and CI (tests, weekly vulnix CVE scan, release tagging). The repo has four prior audit rounds documented (2026-08-14 → 08-30); I verified each previously-open item is actually closed in the code at `d22c5da`, and re-audited the highest-value targets fresh.

## Targets investigated
- **`pkgs/netns-exec` (C, cap_sys_admin wrapper)**: allowlist checked before `snprintf` bounds check, absolute-path `execv`, caps dropped before exec, owner-only `0500` + file caps (no setuid). Clean.
- **lnd macaroon `ExecStartPost` (root)**: atomic rename from root-only staging dir, admin.macaroon read de-privileged via `runuser -u lnd`, response body capped at 64 KiB, `jq -e` fail-closed. I empirically verified the `+` prefix runs **fully unsandboxed** root (it bypasses `ProtectSystem=strict`, which is why the `/run/lnd-macaroons.*` staging outside `RuntimeDirectory` works) — correct today, but a latent footgun.
- **secrets system**: rpcauth password via file (not argv), symlink-safe enough given root-only dir, dotglob lockdown, fail-closed on missing files. Clean.
- **onion-addresses**: symlink refusal + single-v3-onion content validation (load-bearing for `externalip=$(cat …)` injection). Clean.
- **bitcoind RPC**: `rpcwhitelistdefault=0`, whitelist trimmed of DoS/wallet methods, cookie 0640 documented. Clean.
- **CI/supply chain**: SHA-pinned actions, fail-closed cve-scan, hash-pinned fetches everywhere, GPG-verified release/tag helpers, no curl|bash. Fork PRs get no secrets, so cachix signing key can't be exfiltrated. Clean.
- **Docs**: `permitRootLogin = "yes"` in install.md is scoped to the throwaway install system; final config forces pubkey-only. Acceptable.

No new high or medium findings. The only open substantive item is the already-documented, mitigated wireguard REST bind.
