# Security Audit — ostermayer/nix-bitcoin @ 121406c

## Surface map

Trimmed fork. Ships only: bitcoind, lnd (+lndinit, lndconnect), electrs, btcpayserver/nbxplorer, plus infrastructure (onion-services, onion-addresses, netns-isolation, secrets, backups, operator, presets, deployment via krops/nixops).

Trust boundaries claimed and examined:
- **secrets assembly** (`modules/secrets/secrets.nix`): root `setup-secrets` oneshot, `umask u=rw,go=`, `escapeShellArg` on all interpolations, unlisted files locked to `root:root 0440`.
- **onion-addresses** (`modules/onion-addresses.nix`): root service with `CAP_DAC_OVERRIDE`; copies tor hostname files into service-readable outputs. Bytes are spliced into `bitcoin.conf`/`lnd.conf` (`externalip=$(cat …)`) and the lndconnect admin-macaroon URL (`--host=$(cat …)`).
- **RPC auth**: cookie (group `bitcoin`) + HMAC rpcauth users (`privileged`, `public`, `btcpayserver`); public whitelist is a curated safe set.
- **lnd macaroons**: admin macaroon 0600 lnd; custom macaroons created by a `+`-prefixed root script, staged in a root-only tmpfs dir and moved via `rename(2)`.
- **netns-exec**: capability wrapper (`cap_sys_admin=ep`, owner-only 0500, absolute-path `execv`, caps dropped pre-exec, hardcoded netns whitelist).
- **systemd hardening**: `defaultHardening` (ProtectSystem=strict, NoNewPrivileges, MemoryDenyWriteExecute, CapabilityBoundingSet="", …) applied to all daemons.
- **packaging**: all fetches hash-pinned HTTPS, no curl|bash, no remote patches; nbxplorer 2.6.10, lndinit 0.1.3-beta.

## Investigation (highest-value targets)

**onion-addresses (121406c fix)** — Verified the new `^[a-z2-7]{56}[.]onion$` regex fails closed on every multi-line injection payload (second-line `shutdownnotify=`, `bitcoind.rpchost=`, evil-first-then-onion, bare injection). bash's `$` anchors to end-of-string (no `REG_NEWLINE`), so any embedded newline breaks the match. Read-once-into-`$content` closes the `-L`-then-`cat` TOCTOU: a raced-in secret can never match the onion shape and is never written downstream. The high-risk splice path (`externalip`) reads from `services/<svc>` (root-owned 0755 dir, 0400 file), not the user-owned `<user>/<svc>` path, so a tor-user → service-user injection is closed. Post-write self-tampering by the owning service is not a boundary crossing (owner == consumer). **Fix is sound.**

**electrs / bitcoind cookie (121406c fix)** — `electrs.toml` now `install -m 600` (was bare `>`). Cookie now explicit `chmod 0640` (was `g=r`, which left other-read at bitcoind's umask). Both correct.

**secrets.nix rpcauth wrapper** — Password passed via file (`sys.argv[2]`), enters only the in-process Python `sys.argv` list, never the OS `cmdline`. `/proc/<pid>/cmdline` shows `<user> <file>`, not the password. Correct.

**lnd macaroon root script** — Staging in root-only 0700 `mktemp -d` on the same tmpfs as `/run/lnd`; final move is `mv -f` = `rename(2)`, which replaces a lnd-planted symlink rather than following it. lnd cannot redirect the write to an arbitrary target. Correct.

**netns-exec** — Absolute-path requirement, `execv` (not `execvp`), cap returns checked, nonzero exit on exec failure, whitelist matches the trimmed service set. Correct.

**No secrets in /nix/store** — `builtins.toFile`/`writeText` configs contain only paths, usernames, and salted rpcauth HMACs (not plaintext). All plaintext passwords are appended in `preStart` to 0600 files. Confirmed.

## Notes on things checked and cleared

- `bitcoind-rpc-public-whitelist.nix`: DoS/side-effect methods (`scantxoutset`, `gettxoutsetinfo`, `getblocktemplate`, `getblockfrompeer`, `fundrawtransaction`) removed; `getpeerinfo`/`getnodeaddresses` retained with a clear rationale (lnd chain-backend health check). `mkDefault`-overridable.
- `bitcoind-remote.nix`: `rpcpassword` line rewritten via `sed -i '/^rpcauth=/d'` + append, `chmod 0640`; no more unbounded growth, not world-readable.
- `fetch-release`: refuses to fetch upstream fort-nix releases unless `NIX_BITCOIN_FETCH_UPSTREAM` is set; GPG-fingerprint-pinned.
- `overrides.nix`: empty (no stale security overrides lagging).
- netns setup services (`nb-netns-bridge`, `netns-*`) legitimately lack `defaultHardening` because they require `CAP_NET_ADMIN`/iptables/netns manipulation; they are oneshot infrastructure, not input-handling daemons. Acceptable.
- `secure-node.nix` enables `dbusHideProcessInformation` and doas-over-sudo; bitcoind `listen=true` binds to `127.0.0.1` + onion port only.
