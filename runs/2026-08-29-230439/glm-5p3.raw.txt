## 3. Highest-value targets, re-verified

**lnd macaroon ExecStartPost (HEAD commit, the 2026-08-30 high fix).** Read path now runs `runuser -u lnd -- xxd admin.macaroon` by store path; a planted symlink fails closed (lnd cannot read what lnd cannot read) and `set -eo pipefail` from `rootScript` makes the failure visible, not silent. Write path stages in a root-only mktemp dir on the same tmpfs and lands via `mv -f` (rename(2), never follows a destination symlink). lnd cannot write `/run` itself, cannot enter the staging dir, and cannot redirect the REST URL (`nbLib.address` maps 0.0.0.0 to 127.0.0.1). The regression test runs in the default CI scenario (base config sets `lightningBackend = mkDefault "lnd"`, so the macaroon exists). Fix is correct and complete. No bypass found.

**Secrets subsystem.** rpcauth gets its password via file into an in-process `runpy` (no OS argv exposure). Unlisted files locked to root:root 0440, dir 0751 traverse-only, service users cannot replace or write their 0440 secret files. No secret content reaches any store path (all runtime-appended in preStart at 0600/0640).

**onion-addresses root reader.** Refuses symlinks, validates exact v3 shape before the bytes are spliced into bitcoin.conf/lnd.conf/lndconnect URLs, reads once into a variable (TOCTOU-safe), builds output dirs root:root 0700 and hands ownership over only at the end, `chown -h` everywhere, capability set bounded to file caps.

**netns-exec.** Whitelist matches the shipped service set, absolute-path exec, caps dropped before exec, returns checked, wrapper is owner-only 0500 with cap_sys_admin=ep.

**RPC boundaries.** Public/btcpayserver whitelists carry no DoS or wallet-side-effect methods (getpeerinfo/getnodeaddresses retention is justified: lnd's health check needs them). The `.cookie` group grant remains documented-by-design. btcpayserver's lnd macaroon is read-heavy with invoice/address write only.

All fixes from the 2026-08-14 and 2026-08-29 audits were confirmed present in code, not just in commit messages.
