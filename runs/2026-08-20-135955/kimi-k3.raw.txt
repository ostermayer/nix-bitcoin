I've completed the audit. Summary of the investigation before the findings:

## Surface map and what I checked

**Read end-to-end (fork's own code):** `modules/` — bitcoind, lnd, electrs, btcpayserver/nbxplorer, lndconnect, backups, nodeinfo, operator, security (D-Bus policy), netns-isolation, onion-services, onion-addresses, secrets/secrets.nix, all presets (secure-node, hardened, hardened-extended, enable-tor, wireguard, bitcoind-remote), deployment/krops+nixops, versioning/obsolete-options; `pkgs/` — lib.nix hardening helpers, netns-exec C source, lndinit, nbxplorer, overrides, nixpkgs-pinned, krops pin; `helper/` and `test/ci/` scripts; CI workflows; examples and docs.

**Verification methods:** diffed every kept module against archived upstream `fort-nix/nix-bitcoin` to isolate fork deltas (nearly all are genuine tightenings); evaluated a full config (`bitcoind+lnd+electrs+btcpayserver+lnd-backend`) with `nix eval` and inspected the resolved systemd units to confirm `defaultHardening` actually merges (`NoNewPrivileges`, `ProtectSystem=strict`, `PrivateUsers`, `PrivateTmp` all present on funds services) and that no secret value reaches a store path (all `$(cat ${secretsDir}/…)` uses are runtime `preStart`, configs in the store carry only paths); recomputed umask math on the new lnd macaroon staging (0440 owner-only, root-only staging dir, atomic rename — the symlink race is closed); traced the onion-addresses root script (the residual `-L`-then-`install` TOCTOU has no attacker payoff: tor plants the symlink but the copy lands readable only by the target service/operator, so I dropped it); checked `netns-exec` (owner-only 0500, fscaps → AT_SECURE neutralizes `LD_*`, absolute-path exec, caps dropped before exec).

**Prior-audit fix verification:** the 2026-08-14 audit's claimed fixes (M-2/M-3/M-4/M-6, L-6/L-8/L-11) are all real and complete in the code. The cookie group grant (L-10) is explicitly documented as accepted design.

## Findings

The one substantive defect: the fork hardened its code and explicitly refuses to fetch upstream releases ("would silently ship un-fixed code"), yet its own user-facing onboarding (flake templates, examples README, install doc) still points new users at the archived `fort-nix/nix-bitcoin` — which permanently lacks every fix this fork shipped (clightning-rest `0.0.0.0` admin API, lndconnect admin rebind, the RPC DoS whitelist, nbxplorer 2.6.10, the macaroon races). A user following the fork's own docs gets the unpatched upstream.
