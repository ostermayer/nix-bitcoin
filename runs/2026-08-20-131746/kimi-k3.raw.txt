I have completed the audit. Here is a summary of the investigation.

## Surface map

Trimmed fork: `bitcoind`, `lnd`, `lndconnect`, `electrs`, `btcpayserver`/`nbxplorer`, plus infra modules (`secrets`, `onion-services`/`onion-addresses`, `netns-isolation`, `operator`, `security`, `backups`, presets) and `pkgs/` (`lib.nix` hardening, `lndinit`, `netns-exec`, `nbxplorer`). I focused where funds/keys/root are reachable: `lnd.nix`, `bitcoind.nix`, `secrets/`, `onion-addresses.nix`, `operator.nix`, `netns-isolation.nix`, and everything that moves secrets.

## What I verified clean

- **No secrets in the Nix store.** All secret material is assembled at runtime in `preStart` (`install -m 600/640`, `cat $secretsDir/...` appended to config files in service-owned data dirs). The RPC-password HMAC generation (`modules/secrets/secrets.nix:76-96`) was already fixed to pass the password via file, not argv. `preStart`/`postStart` run as the service user (no `+` prefix), so the `install -o bitcoin` idiom in `bitcoind.nix:418` is same-user and not a root primitive.
- **RPC whitelist** is default-deny (`rpcwhitelistdefault=0`), and commit be5e094 removed the wallet/DoS over-grants. `getpeerinfo`/`getnodeaddresses` remain, documented as lnd requirements.
- **`onion-addresses.nix`** (the historical symlink-privesc class) now refuses symlink sources, uses `chown -h`, and populates root-only dirs before handing them over. The M-4 fix from the prior audit is real.
- **Fetchers** are all hash-pinned (`lndinit`, `nbxplorer`, `rpcauth.py`, nixpkgs tarballs via `flake.lock`); `overrides.nix` is empty; the ecdsa meta-stripping was removed with the trim.
- **netns-exec** allowlists namespace names, requires absolute exec paths, drops all caps before `execv`.
- **operator** is root-equivalent by design (sudo/doas NOPASSWD to service users, root's SSH keys in secure-node) — trusted role, not a finding.

## Findings

**1. lnd macaroon creation: root TOCTOU in lnd-writable `$RUNTIME_DIRECTORY` (the headline finding).** Commit 9b71bec fixed pre-planted *destination* symlinks via mktemp+rename, but the mktemp file is created *inside* `/run/lnd`, which the `lnd` user owns (`RuntimeDirectoryMode 711`). The `ExecStartPost` runs via `nbLib.rootScript` = `+` prefix, which per `systemd.service(5)` runs with **full privileges — User= and all filesystem namespacing (ProtectSystem, PrivateUsers, etc.) not applied**. Between `mktemp` (lnd.nix:276) and the `chmod`/`chown` (lnd.nix:283-284) the lnd user can unlink the temp file and plant a symlink. The window is attacker-controlled and huge: the curl in between talks to *the attacker's own lnd REST endpoint*, so a compromised lnd delays the response for seconds and swaps at leisure. `chmod ug=r,o=` and `chown btcpayserver:` follow the symlink → **root chmod 0440 + chown of an arbitrary file to the btcpayserver user**; the final `mv` then installs the symlink as `/run/lnd/btcpayserver.macaroon`, and btcpayserver (ordered `after` lnd) reads that file as its macaroon and transmits the contents as the `Grpc-Metadata-macaroon` header to the attacker's own endpoint — a clean arbitrary-root-file exfiltration channel. Target: `/etc/nix-bitcoin-secrets/bitcoin-rpcpassword-privileged` (unrestricted RPC user, no whitelist → wallet drain if the bitcoind wallet is enabled), `/var/lib/bitcoind/.cookie`, SSH keys, `/etc/shadow`. A tighter, retryable variant (swap before the pipeline's redirect opens; lnd can crash-loop itself for unlimited retries since `ExecStartPost` re-runs on every start) yields root arbitrary file *write* with attacker-controlled content → RCE. Fix: stage the temp file where lnd can't write, e.g. `mktemp /run/.${macaroon}.XXXXXX` (`/run` is root-owned 0755), then chmod/chown/mv as today — the rename into place is already destination-symlink-safe.

**2. `hardened-extended.nix:56` sysctl typo** — `"syskernel.core_pattern" = "|/bin/false";` should be `kernel.core_pattern`. systemd-sysctl logs and skips the unknown key, so the stated "disable core dumps" control silently never applies; lnd/bitcoind crashes persist memory (key material) to `/var/lib/systemd/coredump` instead of discarding it. Real defect, limited direct exposure (dumps stay root/owning-user readable).

**3. Info:** residual TOCTOU between the `-L` check and `install` in `onion-addresses.nix` (`copyOnionFile`). Exploiting it needs a tor compromise plus a blind microsecond race (one attempt per tor restart) plus a second compromise to read the output — below the bar for a vulnerability, noted for completeness.
